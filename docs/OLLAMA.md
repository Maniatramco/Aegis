# Local-only Ollama development

Ollama is an explicit provider for chat, JSON-schema extraction, and embeddings.
The adapter calls only `http://127.0.0.1:11434`, ignores HTTP proxy environment
variables, sends no credentials, follows no redirects, and has no cloud fallback.
Remote/cloud model names are rejected. Keep the Ollama daemon in local-only mode.
Answers are generated by the downloaded model, not by a ChatGPT subscription.

This native development workflow uses SQLite, a Python worker, persistent files,
and local vector search. It is separate from the supported Compose deployment.
The fixed loopback endpoint cannot reach a host Ollama daemon from a container;
do not change it to an untrusted remote URL or expose the daemon publicly.

## Models and resources

- `qwen3:4b`: approximately **2.5 GB**, Apache 2.0; chat and extraction.
- `nomic-embed-text`: approximately **274 MB**, Apache 2.0; embeddings.
- Ollama v0.35.1 Windows standalone download: approximately **1.47 GB**;
  the runtime needs additional unpacked disk space (official guidance: 4 GB).
  Ollama is MIT licensed; bundled dependencies retain their own licenses.

Sources: [Qwen3](https://ollama.com/library/qwen3:4b),
[Nomic](https://ollama.com/library/nomic-embed-text),
[Windows runtime](https://docs.ollama.com/windows),
[Ollama license](https://github.com/ollama/ollama/blob/main/LICENSE).

A 6 GB NVIDIA GPU is a reasonable starting point for Qwen3 4B at the adapter's
4K context. Actual speed and available memory depend on other applications.
Use one request and one loaded model at a time on a 16 GB laptop. Close unused
applications if RAM is tight. Larger documents may need smaller extraction
selections; a small local model is not a guarantee of extraction accuracy.

## Windows setup

Install the official free Ollama runtime, or unpack its standalone Windows zip
outside the Git checkout and add its directory to this terminal's PATH. No cloud
account, payment details, subscription, or API key is needed.

In a dedicated PowerShell terminal, start the local daemon:

```powershell
$env:OLLAMA_NO_CLOUD='1'
$env:OLLAMA_HOST='127.0.0.1:11434'
$env:OLLAMA_NUM_PARALLEL='1'
$env:OLLAMA_MAX_LOADED_MODELS='1'
$env:OLLAMA_CONTEXT_LENGTH='4096'
ollama serve
```

Use a second terminal to download models and install Aegis dependencies:

```powershell
ollama pull qwen3:4b
ollama pull nomic-embed-text
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.txt
cd frontend
npm ci
cd ..
.\.venv\Scripts\python.exe scripts/windows-dev.py start
```

The launcher generates private `.env` secrets only if that file does not exist.
It leaves existing data and configuration intact. It binds the app to loopback,
sets `AEGIS_LOCAL_ONLY=true`, selects Ollama, and removes inherited OpenAI/OCI
keys from child environments. `--mock` is available for explicit synthetic tests.
Start refuses to overwrite a recorded run or take over occupied app ports.

Open http://127.0.0.1:3000. Copy `AEGIS_BOOTSTRAP_TOKEN` privately from `.env` into
the setup screen and choose your own administrator password. Never commit or
share the token/master key. On Windows these files inherit the account folder's
ACLs; POSIX chmod bits are not a Windows access-control mechanism.

In Connections, choose **Ollama** for generation and embeddings, with `qwen3:4b`
and `nomic-embed-text` respectively. Save a named connection profile. Register
one chat/extraction model and one embedding model using that profile. Map them
to a dataset and select its defaults. Upload a synthetic TXT first, wait for
Ready, and ask a question. Ollama needs no external-processing consent when
storage and search remain local. Existing embeddings must be reindexed after
switching provider/model; the index fingerprint distinguishes Ollama model names
and dataset index generations from previous providers. Reindex also after
updating the weights behind a model tag.

Local-only mode rejects cloud provider settings and queued/pinned cloud model
executions. It does not alter global Windows networking/firewall settings.
Do not sign in to Ollama Cloud or enable cloud features for this workflow.

Stop the app (data is preserved):

```powershell
.\.venv\Scripts\python.exe scripts/windows-dev.py stop
```

Stop the dedicated Ollama terminal with Ctrl+C. Default app data/logs and PID
records are under ignored `data/native-windows`. An existing installation may
use `--runtime-dir PATH`; pass the same directory for start and stop.

## Verification

```powershell
cd backend
..\.venv\Scripts\python.exe -m pytest tests/test_ollama.py -q
$env:AEGIS_TEST_OLLAMA='true'
..\.venv\Scripts\python.exe -m pytest tests/test_ollama.py -k real_ollama -q
```

The opt-in test uses an isolated temporary database and the existing test
authentication fixture, never a persistent user administrator. It performs real
local embedding/indexing, retrieval, cited chat, and structured extraction on
synthetic data. Ordinary CI tests mock the loopback transport and require no
model downloads. Ollama answers currently use the application's buffered async
fallback, so the completed answer appears together rather than token by token.
